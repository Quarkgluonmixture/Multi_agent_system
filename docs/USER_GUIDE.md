# 使用指南

本文对应 Multi AI Chat v0.79，介绍主聊天工作区的日常操作和常见故障处理。安装步骤见仓库根目录 [README](../README.md)。

## 第一次运行

1. 在 `chrome://extensions` 加载仓库根目录后，先分别打开 ChatGPT、Gemini、DeepSeek、Kimi 并完成登录。
2. 点击扩展图标。扩展会创建一个独立、最大化的 `chat.html` 窗口；再次点击会聚焦已有窗口。
3. 如果某家一直显示 preparing 或 submitting，点击“看 Grid”，确认对应 iframe 没有登录、地区限制、条款确认或验证码页面。
4. 处理完网页提示后隐藏 Grid，再发一条短问题做冒烟测试。

专用窗口是运行机制的一部分。关闭它会结束当前工作区；把它留在自己的 Chrome 窗口中，可以降低网页流式响应被后台节流的概率。

## 一次 pipeline 会发生什么

### R1：独立回答

每个已启用 provider 收到同一份用户问题和之前的对话历史，但看不到其他 provider 本轮的回答。它们按结构化模板给出结论、推理、盲点、不确定性和建议。

### R2：角色化交叉评审

成功完成 R1 的 provider 会读到所有 R1 输出，并按分配角色重新审议。默认角色映射写在 `background.js` 的 `DEFAULT_ROLE_MAPPING` 中，目标是让不同模型主动寻找反例、证据缺口或执行问题，而不是简单互相复述。

### Final：主编合成

主编读取成功的 R2 输出，生成最终结论、综合答案、共识、分歧裁决、可执行方案和仍需验证的信息。Final 生成时，当前文本会流式显示在聊天界面。

R1 至少需要两份有效输出才能进入 R2，R2 也至少需要两份输出才能进入 Final。瞬时提交或抓取失败会自动重试一次。

## 聊天操作

- **发送**：Enter 发送，Shift+Enter 换行。
- **排队**：pipeline 运行期间继续发送，消息会显示为 queued，并在当前轮结束后依次执行。
- **停止**：取消当前 pipeline；普通新消息取消后会回到输入框。
- **编辑**：编辑某条用户消息会截断其后的对话并从该位置重跑。
- **重新生成**：对最后一轮重新执行 pipeline，不重复追加用户消息。
- **查看推理过程**：展开最终回答附带的 R1/R2 原始结果。
- **新对话**：清除当前扩展对话；不会自动删除各 provider 网站上已经产生的普通会话。
- **主题**：浅色/深色选择保存在本地。

参与者和主编的选择也会持久化。参与者不能少于两家；主编可以是未参与 R1/R2 的另一家 provider。

## Grid 与 Gemini 历史

“看 Grid”把聊天 UI 后面的四个 provider iframe 暂时显示出来，主要用途是：

- 完成登录、同意条款或人机验证；
- 确认 prompt 是否确实进入编辑器；
- 检查模型是否仍在生成；
- 判断是 adapter 失效还是服务商网页本身报错。

“清 Gemini”会新开一个 Gemini 顶层页面，逐条点击它识别到的对话菜单和删除确认。这会真实删除 Gemini 历史，无法由本扩展恢复。网页文案或 DOM 变化时，它也可能只删除一部分；请始终检查返回统计和 Gemini 页面。

## Debug bundle

点击“Debug”会复制 Markdown 格式的诊断信息，主要包括：

- workspace tab 和 provider frame 注册状态；
- 每家 provider 的页面探针与生成状态；
- R1/R2/Final 各阶段最近一次结果；
- prompt 注入路径及 selector 错误；
- service worker 记录的近期错误。

报告可能包含页面 URL、错误文本和回答片段。转发前请人工检查并删除私人问题、账号信息或其他敏感内容。

## 常见问题

### 一直停在 preparing

先显示 Grid，确认对应站点已经登录且 iframe 内页面正常。然后在 `chrome://extensions` 重新加载扩展并重开聊天窗口。若只有一家失败，可先临时禁用它，保留至少两家继续运行。

### prompt 已填入但没有发送

Gemini、ChatGPT 和 Kimi 使用复杂的富文本编辑器，网页更新后可能改变事件处理。保持聊天窗口可见，显示 Grid 检查发送按钮；复制 Debug bundle 时重点看 hijack outcome 和 submitting 阶段。

### 回答生成了但扩展一直等待

adapter 会综合生成按钮、消息状态和文本稳定时间判断结束。长推理模型可能在“思考结束”后延迟显示正文，因此不要过早关闭窗口。确认页面已完成后仍不返回，记录 Debug bundle 再更新相应 selector 或完成判定。

### Final 主编失败

主编不需要参加 R1/R2，但它必须已登录且 iframe 可用。切换到另一家主编后重试；如果 R2 成功结果已显示，Debug bundle 也可用于手工恢复内容。

### 对话历史在哪里

扩展当前会话保存在 `chrome.storage.local` 的 `conversation` 键中，回答条目包含 Final 文本及其 R1/R2 映射。它不是加密数据库，也没有跨浏览器同步保证。清除扩展存储或删除扩展会丢失这些记录。

## 更新后的检查

每次拉取新版本后：

1. 在 `chrome://extensions` 重新加载扩展。
2. 关闭旧的 Multi AI Chat 窗口，再点击扩展图标重开。
3. 显示 Grid，确认四家登录状态。
4. 用一句短问题跑完整 R1/R2/Final。
5. 检查最终回答、展开的 rounds、取消按钮和 Debug bundle。
